# 架构说明

本文描述当前系统结构；如果需要理解项目为什么这样分层、应按什么顺序阅读源码，
以及一个项目从需求到测试维护的完整过程，请先看
[代码阅读指南](code_reading_guide.md)。

## 总体结构

NovelMind 采用前后端分离的轻量结构：

- `backend/`：FastAPI 后端服务。
- `frontend/`：Streamlit 前端展示页面。
- `data/`：本地开发数据目录。
- `docs/`：项目文档。

运行时基线为 Python 3.12。FastAPI 和 Streamlit 都只监听
`127.0.0.1`；Streamlit 配置显式开启 CORS 与 XSRF 防护，不对局域网或公网
提供服务。

## 后端目录

- `backend/app/main.py`：FastAPI 应用入口。
- `backend/app/api/`：FastAPI 接口路由。
- `backend/app/core/`：配置、数据库连接和版本迁移。
- `backend/app/models/`：SQLAlchemy 数据模型。
- `backend/app/parser/`：小说章节解析逻辑。
- `backend/app/rag/`：外部 embedding、向量快照、本地检索和 RAG 回答编排。
- `backend/app/analyzer/`：模型契约、DeepSeek 客户端、摘要、人物和报告任务。
- `backend/tests/`：pytest 单元、接口、迁移和并发测试。

## 当前数据流

1. 用户上传 TXT 小说。
2. Streamlit 通过 HTTP 把文件字节发送到 FastAPI。
3. 后端检查文件类型、大小和编码，并解析小说章节。
4. 小说和章节信息保存到 SQLite。
5. 前端通过分页接口展示资料库和章节元数据，只在阅读时获取单章正文。
6. 用户在摘要工作区查看外部处理范围并明确同意发送正文。
7. 后端创建持久化任务，以异步请求并发生成互不依赖的章节摘要；协调器逐条
   校验结构化 JSON，并串行写入 SQLite 和更新进度。自动调度在稳定完成后扩容，
   遇到可重试的限流或服务错误时减半降速；前端通过任务接口恢复进度并分页读取结果。
8. 用户在人物工作区再次确认外部处理与内容权利；后端按章或片段调用
   DeepSeek 分页提取人物观察，再调用 DeepSeek 完成全书人物归并和关系推理。
9. 后端严格校验模型返回的本地观察 ID、人物档案分区、关系端点和证据章节，
   然后在同一事务中替换当前人物快照；本地只计算提及数、覆盖章节和分页统计。
   任务进度以正常预计生成步骤初始化；分页或人物消歧产生额外调用时会动态扩展
   总步骤，极端安全上限只用于调用边界披露，不作为用户进度。
10. 用户在 RAG 工作区确认外部处理后，后端确定性切分章节，并调用阿里云
    硅基流动 `Qwen/Qwen3-Embedding-4B` 生成 1024 维向量。
11. 新向量先写入版本化本地向量集合；数量校验通过后才在 SQLite 事务中
    切换当前索引。未变化片段可从旧集合复用，失败时旧索引继续可用。
12. 提问时问题先发送至硅基流动生成查询向量；本地 SQLite + NumPy 精确检索，
    后端重新从
    SQLite 截取并校验原文，再把问题和证据发送至 DeepSeek。
13. DeepSeek 只能引用本次检索到的片段 ID；答案、证据和引用保存到 SQLite，
    Streamlit 按纯文本展示。
14. 报告任务先复核全部章节摘要的标题/正文来源哈希；有效人物快照可作为
    可选派生输入，报告阶段不再次发送小说正文。
15. 长篇摘要由 DeepSeek 分批提炼为带章节序号的证据笔记，并继续通过
    DeepSeek 分层归并；最终报告的每个部分都必须引用当前小说的章节序号。
16. 最终结构和引用校验通过后才原子替换 `novel_reports` 当前快照；任何
    外部调用、来源变化或保存失败都会保留旧报告。

## 前端目录

- `frontend/streamlit_app.py`：页面入口和界面渲染。
- `scripts/novelmind_launcher.py`：本地进程管理器，串行完成后端健康检查、前端
  就绪检查、重复启动保护、日志重定向和安全停止；只监听随机的本机控制端口。
- `frontend/api_client.py`：集中调用 FastAPI，并保留 HTTP 状态码供界面决策。
- `frontend/ui_styles.py`：集中保存页面样式，避免业务代码中混入大量 CSS。

前端通过环境变量 `BACKEND_URL` 获取后端地址，未配置时默认使用
`http://127.0.0.1:8000`。

## SQLite 数据库

默认数据库文件为 `data/novelmind.db`，后端启动时自动建表并执行有版本记录的
幂等迁移。可以通过环境变量 `DATABASE_URL` 修改数据库地址。

当前核心表包括：

- `novels`：保存文件名、文本编码、章节数和创建时间。
- `chapters`：保存所属小说、章节顺序、标题、正文和字符数。
- `chapter_summaries`：保存结构化摘要、来源哈希、模型和提示词版本。
- `analysis_jobs`：保存任务范围、状态、进度和安全错误信息。
- `chapter_character_extractions`：保存逐章人物观察、来源哈希、模型和提示词版本。
- `character_analyses`：保存每部小说唯一的当前人物分析快照及来源信息。
- `characters`：保存当前快照中的规范人物档案和本地聚合计数。
- `character_appearances`：保存人物在各章的提及数和出场摘要。
- `character_relationships`：保存同一快照内的人物关系及证据章节。
- `rag_indices`：保存每部小说唯一的当前本地向量集合指针、来源哈希、模型、
  维度、分块版本和数量。
- `rag_chunks`：保存当前索引中每个向量对应的章节与精确字符范围，不复制正文。
- `rag_questions`：保存 RAG 问答后台状态、问题、检索证据、答案和引用。
- `novel_reports`：保存每部小说唯一的当前结构化报告、来源哈希、模型、
  提示版本和输入覆盖范围。

一个 `novel` 可以关联多个 `chapter`。小说与章节在同一个事务中保存，
避免出现只保存小说但章节不完整的情况。SQLite 外键默认启用，删除小说会
级联删除章节、摘要、任务、向量记录、问答和报告。partial unique 索引确保
同一小说、同一任务类型
最多只有一个 `queued` 或 `running` 任务。
所有后台任务都先持久化再移交执行器；数据库提交后的响应组装和后台派发属于
同一个受补偿保护的窗口。任何一步失败都会用独立会话和 SQLite 锁重试将记录
转为终态，并关闭尚未移交的外部客户端，避免出现没有工作线程的永久排队任务。

当前迁移版本为 9：第 2 版加入摘要与任务表，第 3 版加入任务目标章节和
活动任务唯一索引，第 4 版持久化 `force_refresh`，第 5 版加入人物缓存、
人物快照、出场和关系表，第 6 版加入 RAG 索引快照，第 7 版加入 RAG 问答
历史，第 8 版加入全书报告快照，第 9 版在保留现有 RAG 记录的情况下允许
可配置向量供应商、模型和维度。后台执行始终以数据库中保存的任务范围和
force 值为准，不依赖进程内回调参数。

## 模型边界

- 本地不运行大语言模型或 embedding 模型。
- `backend/app/analyzer/llm.py` 定义提供商无关的结构化生成契约。
- 模型配置以 `.env` 为默认值；前端覆盖值原子保存到本机
  `data/model_settings.json`。读取接口只返回密钥是否存在，不返回正文。
- DeepSeek 预设只接受官方 HTTPS 地址；硅基流动预设只接受官方 API 地址，
  并固定 `Qwen/Qwen3-Embedding-4B`、1024 维。
- 生成与 embedding 均可选择 OpenAI 兼容端点。外部端点强制 HTTPS，
  只有 localhost 允许 HTTP；地址禁止凭据、查询参数和片段。
- 配置写入与恢复接口只接受回环地址请求；切换供应商必须同时提供新密钥，
  或明确清除密钥并进入未配置状态，防止把旧密钥误发到另一个端点；API Key
  会先去除首尾空白再参与校验。
- 运行中的任务持有启动时的不可变配置快照；后续请求使用新配置。
- 本地向量库使用 SQLite 保存外部 API 返回的 float32 向量和定位元数据，
  使用 NumPy 执行精确余弦检索，不保存原文、不运行本地 embedding 模型。
- 原文只在用户明确同意后发送，日志和任务错误不记录正文、密钥或推理内容。
- 人物归并和关系推理会发送由原文生成的人物观察与档案；界面会与原文范围
  一并披露。人物名称、描述和关系等模型文本在前端只按纯文本渲染。
- 人物抽取响应和后续归并请求均有显式体积、条数和页数上限；模型声明
  `has_more` 时继续走外部 API，重复或耗尽上限会整次回滚，不在本地猜测
  缺失人物。
- 外部处理确认和内容处理权利确认是两个独立门禁；确认通过前不会构造
  DeepSeek 客户端。
- 超长章节按段落切分并分层归并；估算接口使用同一切分算法展示最大尝试数。
- 章节摘要使用支持异步请求的专用生成客户端；人物、RAG 回答和报告仍使用同步
  生成客户端。两类依赖工厂显式分离，避免同步流水线误收异步专用客户端。
- RAG 建索引和提问分别披露发送到所选向量与生成供应商的数据，并在构造任一
  外部客户端前完成授权校验。
- RAG 当前性同时校验向量供应商、模型、维度、分块版本和来源哈希，切换
  任一配置都会使旧索引过期，避免跨供应商复用。
- 本地向量检索结果必须回查主 SQLite 并重新校验章节、范围和正文哈希；DeepSeek
  引用必须属于本次检索 ID 白名单。
- 报告阶段只发送已验证的派生摘要和可选人物数据；证据提炼、分层归并和
  最终报告均调用 DeepSeek，章节引用必须属于当前小说的章节白名单。
