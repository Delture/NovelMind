## 2. 用户意图与已确定的设计要求

最初要求阅读项目文档，用 pen.dev MCP 设计前端，随后明确要求：**重新设计信息架构与使用流程，不必沿用原 Streamlit 前端布局。**

视觉方向是 Claude + Apple：

- Claude 的暖纸色、陶土强调色、自然文案与阅读感。
- Apple 指现代设计语言：适度圆角、半透明与模糊、悬浮控件、细腻动画；**不是照搬左上角三色窗口按钮**。窗口控制交给系统。
- 少用蓝色、紫色，不堆渐变；内容阅读区保持清晰的对比度。
- 留白要服务信息分组，避免“大卡片里把文字散放在固定坐标上”。姓名、简介、统计、关系等相关信息应紧密组织。
- 原文引用属于辅助信息，使用轻量入口；不要把每条引用做成占据大块空间的按钮。
- AI 回答要有独立内容区、适当边距与分隔，不能与页面文字混成一片。
- 图标使用独立 SVG/图标节点，不用 `⌄`、`···` 等文本字符模拟控件图标。
- 控件默认、聚焦、选中、展开态都要一致。尤其**下拉菜单展开后也必须保持圆角**，不能退回系统默认方形蓝色列表。
- 导入使用统一样式的按钮，隐藏突兀的原生 file input 外观，但保留文件选择和拖放能力。

用户明确反对的繁琐流程：

1. 不要让读者每 50 章手动切换一批目录。目录连续滚动、可搜索与定位当前章；API 分页只能作为内部加载方式。
2. 外部处理确认只在首次使用集中呈现，记住选择；在设置中可查看和修改，不在每个业务页反复勾选。
3. 阅读时不要同时保留全局书架、书内分析导航和章节目录，挤占正文。
4. 后台任务集中管理、自动更新进度，不要求用户手动刷新。
5. 报告缺摘要时，应衔接“补齐摘要并更新报告”，不要让用户来回找页面。

## 3. 当前可体验的原型

### 六个主界面

| 页面 | 文件 | 当前体验 |
| --- | --- | --- |
| 资料库 | `library.html` | 继续阅读、书籍卡片、搜索、导入弹窗、管理入口 |
| 阅读器 | `reader.html` | 连续目录、主题与排版、专注、书签、位置恢复 |
| 章节梳理 | `summary.html` | 全章搜索列表、缺失状态、摘要结果分组、原文跳转 |
| 人物 | `characters.html` | 搜索切换、简介与统计成组、人物关系记录及证据入口 |
| 问答 | `ask.html` | 独立回答卡片、输入区、按需引用抽屉、历史、原文状态 |
| 报告 | `report.html` | 结果为中心、过期提示、阶段内容、补摘要后更新任务演示 |

任务、模型设置、隐私、导入和引用是按需浮层。引用支持“查看证据 → 阅读对应章节 → 返回原来的分析/对话”。

### 阅读器

已实现并验证的前端交互：

- 示例的 128 章连续目录、标题/序号搜索、定位当前章。
- 目录/书签双标签，可收起侧栏；窄窗口采用覆盖式目录。
- 正文独立滚动、上一章/下一章、章末继续、首末章禁用状态与读完提示。
- 纸白、暖纸、夜间；宋体/黑体；字号、行距、正文宽度、段间距即时调整。
- 专注模式隐藏目录，空闲时隐藏工具栏；鼠标移动恢复，Esc 退出。
- 进度面板按章节跳转，显示本章滚动百分比。
- 书签新增、跳转、删除和空状态。
- 阅读位置记录章节、段落、字符偏移；刷新后恢复，不仅仅保存滚动像素。
- Page Up/Down、左右翻章、F 专注、B 书签；输入框内不触发阅读快捷键。
- 减少动态效果支持；离开阅读页时保存位置、清理监听器并移除阅读主题。

第 12 章有自编长篇演示段落；其他章主要为示例内容。不要当成已从数据库加载的真实小说。

实现注意点：

- `app.js` 的 `go()` 获取目标 HTML，替换页面根节点后调用 `init()`。这不是正式 SPA 框架。
- `data-pencil-name` 是大量选择器与事件绑定的接口，改名要检查 JS、CSS 与检查脚本。
- 重导出 HTML 后运行 `python design/rebuild/enhance.py`，否则可能丢失交互脚本关联。
- `reader.js` 必须在 `app.js` 前加载。`readerCleanup` 在离开阅读页时执行。
- 阅读器使用真正的窗口响应式布局；其他页面仍主要是 1440×900 桌面设计并在窄窗口缩放，不能声称全应用都完成了移动端适配。
- `customSelect()` 隐藏原生 select 作为值载体，以 combobox/listbox 呈现圆角菜单，同步 input/change。勿恢复为原生系统下拉弹层。
- 部分代码是紧凑的原型实现，长行较多。正式落地时应适当模块化，不能直接把模拟任务复制到生产任务逻辑中。

## 9. 后续接入建议

用户若继续设计：在 `design/rebuild/` 当前版本上修改，检查默认、选中、展开、空状态、长内容和键盘行为，并同步相关设计源。

1. 做“界面操作—现有 API—返回状态—错误处理—缺失能力”的映射，确认技术栈与部署入口。
2. 接入真实资料库、导入、章节目录和正文，补加载/失败/空数据状态。

4. 接入模型配置、摘要、人物、索引、问答、报告任务；使用真实持久化任务与状态更新。
5. 实现“补摘要→报告”“准备索引→提问”的任务链、失败后保留旧结果、断点恢复。
6. 最后处理万章目录虚拟化、真实预取、分页模式、批注和全文搜索等增强能力。

继续遵循原项目本地单用户边界。不要公开服务、提交密钥/数据库/真实小说，也不要把设计预览中的点击视为用户授权实际付费模型调用。
