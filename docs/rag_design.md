# RAG 设计与实现

## 已实现目标

RAG 基于小说原文回答问题，并返回可核验的章节引用。本地只执行确定性分块、
向量存取、相似度检索、来源校验和任务编排：

- 文档与问题 embedding：阿里云百炼中国（北京）区
  `text-embedding-v4`，固定 1024 维。
- 答案生成：DeepSeek V4 Pro API。
- 向量存储与余弦检索：本地 Chroma。
- 原文、索引指针、切片范围和问答历史：本地 SQLite。

本地不会运行 embedding 模型、大语言模型、语义重排模型或模型推理运行时。
Chroma 始终接收外部 API 已生成的向量，不调用默认 embedding function。

## 数据流

### 建立索引

1. 后端按章节顺序读取 SQLite 原文。
2. 使用版本化的确定性字符分块算法，默认每块最多 1200 字符、相邻块重叠
   200 字符，并优先在段落、换行或中文句末断开。
3. 界面披露发送范围并要求用户分别确认外部处理和内容处理权利。
4. 后端按每批最多 10 个文本调用百炼北京区专属工作空间端点。
5. 严格校验返回数量、索引、模型名、1024 维、有限数值和非零向量。
6. 外部向量写入新的版本化 Chroma 集合；Chroma 元数据只保存章节 ID、
   字符范围和哈希，不保存小说正文。
7. 集合数量完整校验后，在一个 SQLite 事务中切换当前索引指针和切片范围。
8. SQLite 提交成功后清理旧集合。任一步失败都会清理新集合并保留旧索引。

普通更新会按稳定 `chunk_id` 从旧集合复制未变化片段的向量，只把变化片段
发送至百炼。`force` 会禁用复用，并要求界面和后端进行第二次确认。

### 提问

1. 后端确认索引来源哈希、模型、维度和分块版本仍与当前小说一致。
2. 用户分别确认：
   - 问题发送至百炼生成查询向量；
   - 问题和检索片段发送至 DeepSeek；
   - 用户有权将相关内容交给外部服务处理。
3. 百炼返回一个 1024 维问题向量。
4. Chroma 本地检索 3 至 10 个最相关片段。
5. 后端不信任 Chroma 元数据：使用 `chunk_id` 回查 SQLite，重新截取原文，
   再校验章节、字符范围和 SHA-256。
6. 问题与已校验原文证据发送至 DeepSeek。原文被明确标记为不可信数据，
   不能覆盖系统指令。
7. DeepSeek 返回结构化 JSON：答案、`citation_ids` 和证据不足标记。
8. 后端要求引用 ID 唯一且只能来自本次检索结果；充分回答至少需要一个引用。
9. 问答状态、全部检索证据和最终引用保存到 SQLite，界面按纯文本展示。

## 配置边界

`EMBEDDING_BASE_URL` 只接受以下北京区专属工作空间格式：

```text
https://WORKSPACE_ID.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
```

不接受试用端点、其他区域、HTTP、自定义网关、端口、凭据、查询参数或片段。
`EMBEDDING_MODEL` 必须是 `text-embedding-v4`，
`EMBEDDING_DIMENSIONS` 必须是 `1024`。API Key 与端点必须同时配置，
且 Key 必须属于同一区域。

## 一致性与恢复

- SQLite 中每部小说只能有一个当前 `rag_indices` 快照。
- `rag_chunks` 只保存精确原文范围与哈希，不复制原文。
- Chroma 集合名包含小说 ID、来源哈希和任务 ID，不会覆盖活动集合。
- 后台任务在每次真实网络尝试前检查任务和小说仍存在。
- 应用重启会把遗留的活动索引/问答任务标记为失败。
- 启动时会删除没有 SQLite 当前指针的 NovelMind 版本化孤立集合。
- 删除小说后 SQLite 级联删除索引和问答历史，并立即尝试删除 Chroma 集合。

## 隐私与测试

界面会链接阿里云百炼与 DeepSeek 的官方服务条款和隐私政策。真实密钥只保存在
本地 `.env`，不会出现在状态接口、日志、异常、测试数据或 Git 中。

自动化测试使用内存传输、假提供商、临时 SQLite 和临时 Chroma 目录，不访问
真实付费 API。测试覆盖重试、取消、缓存复用、原子快照、来源篡改、伪造引用、
任务恢复、纯文本渲染和孤立集合清理。
